# 官方来源清单 · Official Sources

本文件列出本数据集所依赖的**官方一手来源**（primary sources）。

**核心原则：** 数据集中每一条资格判定，都必须能追溯到本清单中的某个来源。二手来源（中介网站、公众号、AI 生成内容）不作为依据。

**核实日期说明：** 所有来源的最后核实日期为 `2026-09-17`。移民政策随时可能变化，使用前请重新核对。

## 来源可靠性分级

| 级别 | 定义 | 示例 |
|---|---|---|
| **A（最高）** | 目的地国家政府官网、法律文本 | `immi.homeaffairs.gov.au`、`gov.uk`、`mofa.go.jp`、`canada.ca` |
| **B** | 项目本体国际组织官网 | `iaeste.org`、`aiesec.org` |
| **C** | 高校官方部门等可核验机构 | 高校 `.edu.cn` / `.edu.mo` 国际处公告 |
| **D（禁止使用）** | 百科、自媒体、商业博客、来源不明 | 百度百科、知乎、小红书、商业移民博客 |

**本数据集要求：** 每条资格数据至少由 A 或 B 级来源支撑。C 级仅作补充说明。**D 级严禁作为数据来源。**

### 这条规则是自动执行的

`scripts/validate.py` 内置域名分级器（`classify_source`），在 CI 中强制执行：

- 出现 D 级域名（百度百科、知乎、商业博客等）→ **校验失败，阻断合并**
- `publisher` 填写"公开资料""网络资料"等含糊表述 → **校验失败**
- 某项目所有来源都不到 A/B 级 → **校验失败**
- 标注 `primary` 但域名可信度为 C 级 → **告警**，提示复核

> 设计动机：本项目的核心承诺是「每条数据可追溯至官方来源」。
> 一旦来源里混入百科或商业博客，这个承诺就自我瓦解了——
> 而这恰恰是本项目要纠正的"中文互联网信息污染"问题本身。
> 因此这条规则不靠人工自觉，必须由 CI 拦截。

## 如何新增来源

1. 确认来源属于 A 或 B 级
2. 在对应的项目 JSON 文件的 `sources` 数组中添加记录
3. 填写 `type: "primary"`、`url`、`publisher`、`last_verified`、`verified_by`、`claim`
4. 同时更新本文件
5. 提交 PR
