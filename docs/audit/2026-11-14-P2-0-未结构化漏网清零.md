# P2-0 未结构化漏网清零（扫描腿 A1）

> 建表日期：2026-11-14 ｜ 基线 HEAD `4b54d4e` ｜ 范围：`data/programs/*.json` 全 41 个项目

## 1. 目标

结构化字段（`eligibility.*`）之外，`note` 里以自然语言写明的申请要求，如果没有任何机制读它，`judge()` 就会静默判过。本腿逐个项目做一件事：**把 note 全文逐条列成要求清单，逐条对照结构化字段与 judge 机制，找出既没被结构化承接、也没被判读逻辑兜住的那些要求**，并把能影响结论的补上或降级。

## 2. 站规（本轮硬约束）

1. **note 载有结构化字段表达不了的要求时，判定必须降级为「不可判 / 差什么」并给理由，永不静默判过。**
2. **note 与结构化字段冲突时，以 note 为准**（note 是人工回原文后的记录，结构化字段可能是旧值或缺项）。
3. 不改 note 原文；不改 `data/sources`；不做 G6/G8/G9；不碰 web 视觉；不 push。

## 3. 判定线摘录

摘自 `docs/audit/2026-11-12-match-readiness.md` §2 与 §6：

- 三样例画像（A/B/C）判「不可判」占比的**停工线是超过 1/3**。
- 不对称口径（§6）：用户没填语言成绩 + 项目要求语言 → 「差什么」（确定事实）；用户填了语言成绩 + 项目没登记分数线 → 「不可判」；官方不设可比门槛 → 「不适用」，不占不可判名额。
- **起点实测**：画像 C 14/41 不可判 = **0.3415**，为三画像最高值，已贴近/越过 1/3，故对「不可判」只许减不许增 —— 本腿任何修复都必须让不可判数**下降**或持平且理由更硬，不允许靠扩大「不可判」来消除漏网。
