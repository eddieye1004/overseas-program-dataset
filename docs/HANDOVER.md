## 1. 项目是什么

解决一个具体的错误信息问题：中文互联网把**只对中国台湾/中国香港护照开放**的双边互惠项目（加拿大 IEC、英国 YMS、爱尔兰 WHA、日本 WH、韩国 H-1）写成"中国护照可申请"，导致大陆学生准备数月后发现护照不被接受。

本数据集只做一件事：**让每一条资格信息都能追溯到一个官方来源，并标注核实日期。**

设计原则（不可动摇，任何改动不得违反）：
1. **来源可追溯** — 每条资格判定必须附官方 URL
2. **时效可验证** — 每条数据必须有 `last_verified`
3. **护照优先** — 护照类型是第一筛选维度
4. **显式排除** — 明确记录"哪些项目大陆护照不能申请"

### 5.2 强制约束（违反即回退）

1. **一条数据判定 = 一个官方 URL。** 二手来源（中介站、公众号、论坛、AI 生成内容）不作依据；高校部门页面只能标 `secondary` 且不得单独支撑硬资格。

3. **一次提交只做一件事。** 不混入多个不相关项目的改动。
4. **只改被授权的文件。** 上表之外的文件，改之前先问。
5. **交完不等于结束，也不等于可以继续动手。** 报告交付后如需追加改动，先在报告里写明，再改。

## 8. 注意事项（已经踩过的坑，别再踩）

1. **副本唯一性**：只用 `F:\2026-09-17-20-35-22\overseas-program-dataset`。另一个 `F:\2026-10-16-16-35-46\repo\...` 是废弃副本，其 HEAD 已被活副本完整包含。
2. **两个 Python**：`python` → 3.13.14（默认）；`F:\python.exe` → 3.14.6（CA 库缺）。写复现记录时必须写全路径 + 版本，只写版本号会误导。
3. **越界惯性**：T1 期间出现"报告写完 32 分钟后又去改测试"的情况。这不代表能力问题，代表**约束在执行层没有被硬拦截**。请把任务卡里的"禁止"当成硬边界，不是建议。
4. **自证不可信**：任何"我只改了 X"的声明，都要能被 `git status` / `git diff` 支持。交接前 WorkBuddy 会核，Eddie 也会核。
5. **不要把"WARN"等于"失效"**：本机环境下 WARN 几乎全是假警报，根因是 CA 库与反爬，不是数据坏了。
6. **`data/` 是公共契约**：字段改名、枚举增减都会让下游崩，`schema.json` 的改动永远先提案。
